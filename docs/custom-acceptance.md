## Обязательные проверки

- `pnpm run test:acceptance`: реальный sanitizer → HTML converter → Telegram provider с заглушкой отправки; повторное сохранение; опасный HTML; retry/fail-fast; PM2 command guard; shell syntax.
- Полная сборка frontend/backend/orchestrator. Это отдельно от end-to-end приёмки.
- Изолированный стенд: отдельные БД/Redis/Temporal, без production credentials и очередей; проверка схемы и запуска. Нельзя запускать второй worker против production Temporal.
- UI: кнопки и форматирование после сохранения/повторного открытия; API draft readback и отмена; медиа.
- Поведенческая проверка процессов и реальных pollers, восстановления после временного отказа очереди; отсутствие дублей.
- Проверка публикации в согласованном тестовом канале; Instagram требует отдельно разрешённого тестового назначения. Mock-проверка не равна доставке в соцсеть.

## Выкатка и откат

1. Зафиксировать Git SHA, digest кандидата, результаты проверок и предыдущий image ID.
2. Проверить живую очередь и текущие отправки. Не переключать при неопределённом исходе публикации.
3. Сделать защищённые backup конфигурации, Postiz DB, Temporal DB и uploads; проверить восстановление Postiz DB на отдельном экземпляре. Секреты не выводить и не коммитить.
4. Сверить Prisma schema и фактическую БД. Штатный startup использует db push с accept-data-loss; это не разрешение потери данных. Если schema diff разрушительный — остановиться и подготовить отдельный план.
5. Обновить источник конфигурации Coolify и recreate только Postiz. Не менять Temporal/Postgres/Redis одновременно с приложением.
6. Проверить точный образ, HTTP/API, процессы, pollers, интеграции, сохранность draft/scheduled постов и uploads. Общий downtime максимум 15 минут; оставить время на rollback.
7. При провале вернуть старый образ. Если менялась схема, отдельно оценить восстановление БД; не откатывать историю отправок вслепую, иначе возможны дубли.

## Следующее обновление

Новый стабильный tag → отдельная ветка → перенос только нужных групп → acceptance → isolated runtime → согласованная выкатка. Старый работающий образ не перезаписывать. Конфликт или провал проверки блокирует выпуск. Сохранять конкретные результаты; незапущенная проверка не считается пройденной.
