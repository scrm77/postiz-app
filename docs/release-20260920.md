## Эксплуатация

Защищённые backup и машинные отчёты на OVH: `/var/backups/postiz-upgrade-20260920/` (root only). Содержат Postiz/Temporal/Coolify DB, конфигурацию, uploads и результат выкатки. Не публиковать содержимое backup: там секреты.

Скрипты `prepare-upgrade-stage.py`, `start-upgrade-stage.py`, `verify-stage-api.cjs`, `deploy-accepted-release.py` — воспроизводимая запись именно этого выпуска, с явными целевыми именами и версиями. Для следующего релиза обновлять параметры и заново выполнять приёмку, а не запускать вслепую. Workflow build-custom-release.yml собирает кандидата и не разворачивает production автоматически.

На стенде исправлены два отличия от production: до параллельного запуска процессов надо инициализировать PM2 daemon; Temporal должен использовать Elasticsearch, поскольку стандартный SQL visibility ограничивает количество Text search attributes. Изменений в код Postiz по этим двум причинам не потребовалось.

Решение пользователя сохранено в этом репозитории. Запись решения в G-Brain была отклонена `owner_unavailable`; ownership мозга в этой задаче не менялся.
